# Three-minute walkthrough

Use `npm run preview` after a production build. All preview businesses are fictional, provider generation and notifications are disabled, and operator data is not used.

1. **0:00–0:25 — The job.** Open Campaigns. Explain: “A brief should become a campaign the team can inspect, revise, and approve.” Search a campaign, filter its state, then clear the filter.
2. **0:25–1:00 — A usable brief.** Open New brief. Show grouped context, audience/offer, direction, and guardrails. Submit an empty form to show linked errors, then Fill sample. Explain tab-local restoration and deliberate human review.
3. **1:00–1:35 — The actual plan.** Open the saved result. Show the brief disclosure, three angles, landing outline, and seven-day schedule. Point out that deterministic output is labeled and audience observations are hypotheses.
4. **1:35–2:15 — Judgment and revision.** Request a revision with a note, edit an input, and resubmit. Inspect the retained previous version. Approve the new version through the confirmation step.
5. **2:15–2:40 — Take it forward.** Download Markdown and the calendar CSV. Explain that export contains the approved revision and does not publish anything.
6. **2:40–3:00 — Evidence and limits.** Open Workflow. Explain the difference between configured and tested, local templates and live Groq, and local approval and downstream delivery. Link to the case study and verification record.

For a shorter review without saved records, open `/demo`, choose the low-confidence example, and show that approval requires acknowledgment and a note. Start a new example to demonstrate local generation; use Reset to discard only its in-memory state.
